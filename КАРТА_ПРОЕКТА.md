## 1. Родовое дерево (одним взглядом)

```text
Filament Tracker
│
├── main.go                         ← запуск всего (API + воркер в одном процессе)
├── web/                            ← то, что видит человек в браузере
│   ├── index.html                  ← разметка вкладок и форм
│   └── assets/
│       ├── app.js                  ← вся логика UI, запросы к API, тосты
│       └── styles.css              ← внешний вид
│
├── internal/                       ← весь «мозг» на Go
│   ├── config/                     ← PORT, DATABASE_URL, PUBLIC_BASE_URL…
│   ├── bootstrap/                  ← подключение Postgres / Redis
│   ├── domain/                     ← сущности и правила (без HTTP и БД)
│   ├── usecase/                    ← сценарии: создать катушку, старт печати…
│   ├── repository/                 ← сохранение в память или Postgres
│   ├── infrastructure/             ← Bambu Cloud/LAN, шифрование, Redis-клиент
│   ├── delivery/http/              ← HTTP API + раздача web/
│   └── worker/                     ← фоновые проверки (остатки, уведомления)
│
├── db/migrations/                  ← SQL-схема (таблицы, новые колонки)
├── cmd/                            ← альтернативные точки входа (api / worker / migrate)
├── docs/                           ← доп. спецификации
└── .env.example                    ← пример настроек
```

**Правило слоёв** (снизу вверх по ответственности):

```text
Браузер (web/)
    ↓ HTTP / SSE
delivery/http  (маршруты, JSON)
    ↓
usecase        (бизнес-сценарии)
    ↓
domain         (сущности: Spool, Printer, PrintJob…)
    ↑
repository     (memory / postgres)
infrastructure (Bambu, секреты, кэш)
```

Если вы меняете поведение «что система делает» — почти всегда трогаете **usecase** и иногда **domain**.  
Если меняете «как выглядит кнопка» — только **web/**.  
Если меняете «куда пишется в БД» — **repository/postgres** + **миграция**.

## 2. Что есть в системе (предметная область)

Это «члены семьи» — главные сущности:

```text
Катушка (Spool)
    │  остаток веса, материал, цвет, QR
    │
    ├── используется в → Задача печати (PrintJob)
    │                        │
    │                        ├── на → Принтер (Printer)
    │                        └── печатает → Продукт (Product)  [иногда]
    │
    └── учитывается в → Inventory (сводка / транзакции)

Аккаунт Bambu Cloud (CloudAccount)
    └── синхронизирует → список Printer + живые PrintJob
```

| Сущность | Папка domain | Таблица БД (примерно) | Экран в UI |
|----------|--------------|----------------------|------------|
| Катушка | `internal/domain/spool` | `spools` | Склад, Обзор |
| Принтер | `internal/domain/printer` | `printers` | Принтеры |
| Продукт | `internal/domain/product` | `products` | Продукты |
| Задача печати | `internal/domain/printjob` | `print_jobs` | Задачи, Обзор |
| Каталог филамента | `internal/domain/filament` | — (списки в коде) | Форма катушки |
| Cloud-аккаунт | `internal/domain/cloudaccount` | cloud account (миграция 005) | Вход Bambu |

## 3. Куда смотреть по задаче

### «Хочу понять, что делает кнопка в интерфейсе»

1. `web/index.html` — найти кнопку / форму (`id`, `name`).
2. `web/assets/app.js` — найти обработчик (`addEventListener`, `createSpool`, `createPrintJob`…).
3. Там будет `fetchJSON('/api/...')` — это вызов бэкенда.
4. `internal/delivery/http/router.go` — найти тот же путь `/api/...`.
5. Внутри роутера вызывается сервис usecase (`spoolService.Create`, `printJobService.Start`…).
6. Логика — в `internal/usecase/<имя>/service.go`.

### «Хочу понять, откуда берётся печать с Bambu»

```text
Bambu Cloud / MQTT
    → internal/infrastructure/printer/bambu/monitor.go   (слушает принтеры)
    → printJobService.SyncFromBambu(...)
    → internal/usecase/printjob/service.go
    → БД + SSE-уведомление
    → web/assets/app.js подхватывает событие и перерисовывает списки
```

Ключевые файлы Bambu:

| Файл | Роль |
|------|------|
| `infrastructure/printer/bambu/cloud.go` | Вход в Cloud, sync устройств |
| `infrastructure/printer/bambu/auth.go` | Код из email, сессия |
| `infrastructure/printer/bambu/monitor.go` | Фоновый мониторинг печатей |
| `infrastructure/printer/bambu/mqtt_layers.go` | Слои печати из MQTT |
| `infrastructure/secrets/box.go` | Шифрование пароля/токена |

### «Хочу понять остатки пластика»

| Что | Где |
|-----|-----|
| Поля веса катушки | `domain/spool/entity.go` (`CurrentWeight`, `Consume`, `Refill`) |
| Резерв при старте печати | `usecase/printjob/service.go` (`reserveAvailable`, `Start`, `createFromBambu`) |
| Возврат при отмене | там же (`unusedReservedGrams`, cancel/delete) |
| Отображение «сейчас / в будущем» | `web/assets/app.js` (`getSpoolCurrentDisplay`, рендер склада) |
| Метка «догрузите пластик» | бэкенд: `NeedsFilamentTopUp`; фронт: `jobNeedsFilamentTopUp` |

### «Хочу понять уведомления»

| Что | Где |
|-----|-----|
| Хранение / TTL | `usecase/notification/service.go` |
| Публикация с API | `delivery/http/router.go` (`notifier.Publish`) |
| Публикация из монитора | `infrastructure/printer/bambu/monitor.go` |
| SSE-поток в браузер | `delivery/http/sse.go` |
| Тосты и история | `web/assets/app.js` (`mapServerEvent`, `showToast`, `loadNotificationHistory`) |
| Фоновые low/empty | `worker/scheduler.go` |

## 4. Дерево папок `internal/` подробнее

### `domain/` — «что это такое»

Только данные и простые правила. **Не** знают про HTTP, Postgres, Bambu.

Пример: `Spool`, методы `Consume(weight)`, статусы.

Если добавляете новое поле сущности — **начинайте здесь**.

### `usecase/` — «что система умеет делать»

| Папка | Сценарии |
|-------|----------|
| `spool` | Создать катушку, список, публичная страница по QR |
| `printer` | Создать/обновить принтер, cloud-сессия |
| `product` | Создать продукт, цены физ/юр |
| `printjob` | Старт/пауза/отмена, sync из Bambu, резерв пластика |
| `pricing` | Расчёт себестоимости |
| `inventory` | Сводка склада, транзакции |
| `prediction` | Прогноз |
| `notification` | Лента событий |
| `runtime` | Вспомогательная синхронизация |

### `repository/` — «куда сохраняем»

| Реализация | Когда |
|------------|--------|
| `memory/` | Нет `DATABASE_URL` или БД недоступна (данные пропадут после перезапуска) |
| `postgres/` | Есть Postgres; миграции из `db/migrations` |

Интерфейсы репозиториев часто объявлены рядом с usecase или в domain (например, методы `Create`, `GetByID`, `List`, `Update`).

### `delivery/http/` — «вход снаружи»

| Файл | Роль |
|------|------|
| `router.go` | Все `/api/...`, раздача `web/`, сборка сервисов |
| `sse.go` | Server-Sent Events для живых уведомлений |
| `router_test.go` | HTTP-тесты |

Здесь **не** должно быть сложной бизнес-логики — только принять JSON → вызвать usecase → ответить / локализовать ошибку.

### `worker/`

`scheduler.go` — периодические задачи (проверка остатков, алерты). Запускается из `main.go` вместе с HTTP.

## 5. Карта API (куда бьёт фронт)

Все маршруты живут в `internal/delivery/http/router.go`.

| Метод + путь | Смысл |
|--------------|--------|
| `GET/POST /api/spools` | Список / создать катушку |
| `... /api/spools/{id}` | Удаление / правка веса и т.п. |
| `GET/POST /api/printers` | Принтеры |
| `GET/POST /api/products` | Продукты |
| `GET/POST /api/print-jobs` | Список / ручной старт печати |
| `POST /api/print-jobs/{id}/confirm` | Привязать катушку к черновику |
| `POST /api/bambu/cloud/sync` | Войти / отправить код / синк |
| `POST /api/bambu/cloud/resend-code` | Код ещё раз |
| `GET/DELETE /api/bambu/cloud/account` | Статус сессии / выход |
| `GET /api/notifications` | История уведомлений |
| `GET /api/filament-catalog` | Бренды / материалы / цвета |
| `GET /api/health` | Жив ли сервер |
| `GET /public/spools/...`, `/spool/...` | Публичная страница по QR |
| `GET /`, `/assets/...` | UI |

Ошибки API приходят JSON вида `{ status, code, message }`, но `message` уже на русском (и фронт дополнительно переводит через `translateApiError`).

## 7. База данных и миграции

Папка: `db/migrations/` — **единственный источник схемы**.

Файлы идут по номерам (`001_…`, `002_…`, …). Rollback — в `db/migrations/rollback/`.

**Как применяются:**

1. **Docker Compose (рекомендуется):** сервис `migrate` в [`docker-compose.yml`](docker-compose.yml) запускается до `app` и применяет SQL-файлы.
2. **Вручную:** `go run ./cmd/migrate` (читает `MIGRATIONS_DIR`, по умолчанию `db/migrations`).
3. Приложение при старте **не** накатывает схему — только подключается к БД.

Версии пишутся в таблицу `schema_migrations`. Повторный запуск безопасен (идемпотентно).

> Раньше схема была захардкожена в `postgres.Migrate()` — это удалено.

## 8. Конфиг и запуск

1. Скопируйте `.env.example` → `.env`.
2. Важные переменные описаны в `.env.example` (полный typed `config.Settings`).

Ключевые группы:

| Группа | Примеры |
|--------|---------|
| Core | `PORT`, `APP_ENV`, `DATABASE_URL`, `REDIS_*`, `PUBLIC_BASE_URL` |
| Secrets | `BAMBU_SECRETS_KEY`, `SESSION_SECRET` |
| Auth | `ADMIN_USERNAME`, `ADMIN_PASSWORD` / `ADMIN_PASSWORD_HASH` |
| Business | `SPOOL_LOW_WEIGHT_G`, `PRINTER_POWER_KW`, тарифы электричества |
| Intervals | `BAMBU_MONITOR_INTERVAL`, `RUNTIME_SYNC_INTERVAL`, `CLOUD_SYNC_INTERVAL` |

Composition root: `internal/bootstrap` (`NewApp` + `Start`/`Close`).  
HTTP: `internal/delivery/http.NewServer(app)`.  
Публичный конфиг для UI: `GET /api/config`.  
Логин: `POST /api/auth/login` (cookie `ft_session`).

Запуск:

```bash
go run .
```

Открыть UI: `http://localhost:8080` (по умолчанию admin/admin из `.env.example` в development).

Тесты:

```bash
go test ./...
```

## 9. Рецепты: как самому что-то добавить

Ниже — чеклисты. Идите **сверху вниз**. Не пропускайте слой.

### A. Новое поле у катушки / продукта / задачи

Пример: добавить поле «заметки» к продукту.

1. **Domain** — поле в `internal/domain/product/entity.go`, при необходимости в `NewProduct` / конструкторе.
2. **Миграция** — `db/migrations/008_product_notes.sql` (`ALTER TABLE products ADD COLUMN notes TEXT ...`).
3. **Postgres repo** — `INSERT`/`SELECT`/`UPDATE` в `internal/repository/postgres/...`.
4. **Memory repo** — то же в `internal/repository/memory/product.go` (чтобы тесты и режим без БД не ломались).
5. **Usecase** — принять поле в `Create` / `Update` (`usecase/product/service.go`).
6. **HTTP** — JSON в `router.go` (вход и выход).
7. **UI** — поле в `index.html`, чтение/отправка в `app.js`, при необходимости стиль в `styles.css`.
8. **Тест** — расширить `*_test.go` в usecase.

### B. Новый API-эндпоинт

1. Метод в usecase (чистая логика).
2. `mux.HandleFunc("/api/...", ...)` в `router.go`.
3. Вызов из `app.js` через `fetchJSON`.
4. Русское сообщение об ошибке: либо понятный `fmt.Errorf` + `localizeAPIError` в router, либо запись в `translateApiError` на фронте.

### C. Новая вкладка в UI

1. Кнопка навигации + `section.view-panel` в `index.html`.
2. Рендер-функция в `app.js`.
3. Подключить в `loadData` / `bindEvents` / переключение `navItems`.
4. Стили в `styles.css`.
5. Если нужны данные с сервера — сначала пункт **B**.

### D. Новый материал / бренд / цвет в выпадающих списках

Смотрите `internal/domain/filament/catalog.go` (и цвета в `colors.go`).  
API: `GET /api/filament-catalog`.  
Фронт подтягивает списки в `loadFilamentCatalog()`.

### E. Новое уведомление

1. `notifier.Publish("my_type", "Текст на русском", map[string]any{...})` в нужном месте (router / monitor / scheduler).
2. На фронте: `mapServerEvent` + при необходимости `ONESHOT_EVENT_TYPES` / ключ в `eventToastKey`.

### F. Изменение логики резерва пластика / статусов печати

Только `internal/usecase/printjob/service.go` (+ тесты).  
Не дублируйте правила в `app.js` — UI лишь отображает `estimated_weight` / `consumed_weight` / `needs_filament_top_up`.

### G. Поведение Bambu Cloud

Трогайте `internal/infrastructure/printer/bambu/*`, затем убедитесь, что `SyncFromBambu` в usecase по-прежнему корректно пишет задачу.

## 10. Типичный путь запроса (пример)

**Человек нажал «Добавить катушку»:**

```text
index.html  #spoolForm
    → app.js createSpool()
    → POST /api/spools
    → router.go
    → usecase/spool.Create
    → domain: NewSpool + QR
    → repository (memory или postgres)
    → JSON ответ { id, qr_token, ... }
    → app.js loadData() → renderSpools()
    → (опционально) SSE spool_created → тост
```

**Печать появилась в Bambu:**

```text
monitor.go увидел снимок
    → SyncFromBambu
    → частичный резерв катушки (если мало пластика — всё равно создаёт задачу)
    → Publish print_started / filament_short
    → SSE → тост + метка «догрузите пластик» в UI
```

## 12. Чеклист перед коммитом своей правки

1. Понял, какой **слой** меняю (domain / usecase / http / web / db).
2. Если новое поле в БД — есть **новая** миграция.

5. `go test ./...` проходит.
6. Не кладу секреты в git (`.env` с паролями — только локально).
